# スキル編：スキルとはなにかプレゼンテーション

スキルとはなにか（頼み方の手順書）、モデルとの役割の違い、できないことは無理にお願いしないこと、長所を伸ばす書き方、あいまいな頼み方との対比、まとめを扱う、全7枚の資料です。モデル編（ネモトロンの説明）は別資料（[モデル編](model.md)）です。

デザイン判断（デザイン基準 v7）：主色は深いティール #0F6B5C、オレンジ #C26714 は注意の側だけ、中立色 #2B2B28 系、背景 #FDFBF7。モチーフは手順書のチェック線。山場は6枚目（頼み方の対比）。表紙は強く、2〜5枚目は中、7枚目は静かに。全体の宣言は [README](README.md) にある。

様式の宣言：各ページの主役は、主色のベタ面に白文字で作る。薄い色の面は従属の要素だけに使う。チェック線は、それ自体が手順になるページ（2・5・7枚目）だけに置き、見出し帯として全ページに反復しない。ページ型は使い回さない。各スライドの「様式」が、そのページの形の正本。

## 1. スキルとはなにか

様式：表紙。全面ティールに大きな白文字。白いスキルカードを主役に置き、頼む人とモデルは文字だけ。

モデルを変えずに、頼み方を決める手順書の話。

頼む人（仕事を頼む）→ スキル（頼み方の手順書：✓探すもの ✓返す形 ✓分からないとき）→ モデル（仕事をする）

この資料は、スキルの説明だけをします。モデルの説明は、前の資料です。

## 2. スキルは、モデルを変えずに「頼み方」を決める手順書だ

様式：左は文章、右はベタ面の手順書パネル（チェック線はパネルの中身として置く）。

たとえば、料理のレシピや仕事の手順書のようなもの。書いてあるから、頼むたびに説明し直さなくていい。友達そのものではなく、友達への頼み方のメモだよ。

手順書に書くこと：

- 探すものは何か
- 返す形はどうするか
- 分からないとき、どう言うか

レシピや作業マニュアルと同じです。同じ頼み方をすれば、毎回同じ進め方になります。

## 3. モデルとスキルは、役割が違う

様式：モデルは輪郭だけの面、スキルはベタ面。間に ≠ を置く。

- モデル：友達そのもの。できることと、できないことが、ここで決まる
- スキル：頼み方の手順書。頼み方と、進め方が、ここで決まる

注意（オレンジ）：スキルを書いても、できないことが、できるようにはなりません。

## 4. できないことは、無理にお願いしない

様式：悪い頼み方が主役。オレンジのベタ面で大きく置く。渡す先は幅を不均等にし、モデルへの列だけベタ面（従属）にする。

悪い頼み方：「原因を特定して、直して」（取り消し線）

短所に当たらないように、仕事を分けて渡します。

- 解析する → コードへ：決まった処理は機械的に
- 探す・仕分ける → モデルへ：得意な仕事だけを渡す
- 最終判断 → 人・強いモデルへ：責任がいる判断はこちら

## 5. 長所を伸ばす書き方をすると、得意な仕事が返ってくる

様式：チェック線そのものを配置にする。番号の丸を主色の線でつなぐ。

1. 探すものを書く — 例：エラー時刻と、該当する行
2. 返す形を書く — 例：時刻の順に並べて渡す
3. 分からないときの言い方を書く — 例：「分からない」と書く
4. 仕事は1回に1つだけにする — 例：探す、と仕分ける、は分ける

## 6. 頼み方を具体的にすると、答えが使えるものになる

様式：山場。あいまいな側は輪郭だけ、具体的な側はベタ面で大きく。頼み方の文は文節で改行する。

- あいまいな頼み方：「ログを見ておいて」 — 何を探すのかが決まらず、答えが毎回ぶれます
- 具体的な頼み方：「エラー時刻と該当行を抜いて、重さで仕分けて。分からないものは『分からない』と書いて」 — 探すものと返す形が、決まっている

書くのはこの4点だけです。探すもの、返す形、分からないときの言い方、仕事は1つ。

## 7. まとめ

様式：静かに閉じる。チェック線のまとめ3行だけ。

スキルは魔法ではない。得意が生きる頼み方を、書いて残すものだ。

- 短所は、隠さない — 当たらないように、仕事を分ける
- 長所は、伸ばす — 探すもの・返す形・分からないときの言い方を書く
- 頼み方は、残す — 書いて残せば、他の人も同じように頼める

できないことは頼まない。得意な頼み方をする。それだけで、友達はちゃんと役に立つ。
