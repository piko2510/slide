# スキル編：スキルとはなにかプレゼンテーション

スキルとはなにか（頼み方の手順書）、モデルとの役割の違い、できないことは無理にお願いしないこと、長所を伸ばす書き方、あいまいな頼み方との対比、まとめを扱う、全7枚の資料です。モデル編（ネモトロンの説明）は別資料（[モデル編](model.md)）です。

デザイン判断（デザイン基準 v7）：主色は深いティール #0F6B5C、オレンジ #C26714 は注意の側だけ、中立色 #2B2B28 系、背景 #FDFBF7。モチーフは手順書のチェック線。山場は6枚目（頼み方の対比）。表紙は強く、2〜5枚目は中、7枚目は静かに。全体の宣言は [README](README.md) にある。

## 1. スキルとはなにか

表紙。

## 2. スキルは、モデルを変えずに「頼み方」を決める手順書だ

たとえば、料理のレシピや仕事の手順書のようなもの。何をするか、どんな順番でするか、どういう形で返してほしいかが書いてあるから、毎回同じ頼み方になる。友達そのものではなく、友達への頼み方のメモだよ。

## 3. モデルとスキルは、役割が違う

- モデル：友達そのもの。できることと、できないことが決まる。得意なことと、苦手なことは変わらない
- スキル：頼み方の手順書。何を、どう頼むかを決める。頼み方は、得意な形に変えられる

スキルを書いても、できないことが、できるようにはならない。

## 4. スキルを作る時は、できないことは無理にお願いしない

悪い頼み方：「障害の原因を特定して、直して」

仕事を分けます。

- 解析：決まった読み取りは、コードに任せる
- 判断：最終判断は、人や強いモデルに任せる
- 線引き：できない仕事は、スキルに書かない

## 5. 長所を伸ばす書き方をすると、得意な仕事が返ってくる

チェック線の順に、頼み方へ4つを書く。

1. 探すものを書く — エラーの時刻と該当行
2. 返す形を書く — 重さで仕分けた一覧
3. 分からない時の言い方を書く — 推測せず「分からない」
4. 仕事は1回に1つ — あれもこれもと詰め込まない

## 6. 頼み方を具体的にすると、答えが使えるものになる

この資料の山場。あいまいな頼み方と、長所を伸ばす頼み方の対比。

- あいまいな頼み方：「ログを見ておいて」 — 何を探すか分からない。返す形が決まらず、そのまま使えない
- 長所を伸ばす頼み方：「エラーの時刻と行を抜いて、重さで仕分けて。分からないものは『分からない』と書いて」 — 探すものと返す形が決まっている

## 7. まとめ

静かに閉じる。スキルは魔法ではない。得意が生きる頼み方を、書いて残すものだ。

できないことは頼まない。得意な頼み方をする。それだけで、友達はちゃんと役に立つ。
