# モデル編：AIエージェント入門プレゼンテーション

AIエージェント初心者向けに、ネモトロンというモデル／友達の性格・できること・長所と短所をやさしく説明する7枚の入門資料です。これはモデルの説明だけの資料で、スキルの説明は別資料（[スキル編](skill.md)）です。

デザイン判断（デザイン基準 v7）：主色は深いティール #2E8B57、オレンジ #DE8326 はできないこと・短所の側だけ、中立色 #23201A 系、背景 #FFFBF8。モチーフは友達の吹き出し。山場は4枚目（長所と短所）。表紙は迎える強さ、2・3・5・6枚目は中、7枚目は静かに。全体の宣言は [README](README.md) にある。

様式の宣言：各ページの主役は、主色のベタ面に白文字で作る。薄い色の面は従属の要素だけに使う。ページ型は使い回さない（対比のページ同士でも型を分ける）。締めの太字行は、置くページ（山場・まとめ）をここで宣言したページだけに置く。各スライドの「様式」が、そのページの形の正本。

## 1. AIエージェントは友達、怖くないよ

様式：表紙。全面ティールに大きな白文字で、タイポグラフィが主役。役目の文も大きな文字で置く。吹き出しは小さく1つだけ、右寄りに従属として置く（3枚目の大きな吹き出しとは型を分ける）。

モデルの説明 — ネモトロンという友達の話だよ。

吹き出し（友達の自己紹介）：「これを探して」に答えるのが、ぼくの役目だよ

得意と不得意が分かれば、怖くなくなるよ。

## 2. できることと、できないことがあるよ

様式：できることはベタ面＋白い吹き出し、できないことは面なしの文字だけ。下の1行は補足の強さで、締め行にしない。

この資料はモデルの説明だよ。得意と不得意が分かれば、怖くなくなるよ。

- できること：大量のものから探して、抜き出す／まとめて、要約する／手順にそって、手を動かす
- できないこと：最後の判断を下すこと／あいまいな頼み方を読み取ること／間違えない、という保証

人と同じだよ。全部できる友達はいないし、全部できないわけでもないよ。

## 3. ネモトロンは、こんな友達だよ

様式：大きな吹き出し1つに、友達の自己紹介を入れる。中心＋周囲の図（ハブ図）にはしない。名前タグを吹き出しに重ね、役目の文だけ大きくする。

- 小さくて、とにかく速い
- 目がよくて、探しものが得意
- 仕事場は、大量のログの中
- 「これを探して」に答えるのが役目だよ（大きく）

## 4. ネモトロンは、探すのは得意で、つなげて考えるのは苦手だよ

様式：山場。長所はベタ面（白文字）で広く、短所は面なしの文字だけ。型は2枚目と分ける。締め行を置く。

長所：

- 探す・抜き出す — 大量のログから、頼まれた行を見つける
- 突き合わせて仕分ける — 並べて比べて、重さや種類で分ける
- 要約して、一次振り分け — まず大まかに分けて、人へ渡す
- 65k — 渡しても、検索・抽出は保った（キミさんの実測だよ）

短所：

- 複数をまたぐ推論 — 資料をまたぐと、見失いやすい
- 原因の連鎖を追う — なぜそうなったかは、追いきれない
- 知らないものを間違える — 知ってるものだと思い込む
- 長い作業では目的を忘れやすい

締め：長所も短所も、この友達の性格だよ。どちらも知っておくのが大事だね。

## 5. 得意が生きる仕事は、こんな仕事だよ

様式：横の流れ。両端（大量のログ／人）は小さく、中の3つはベタ面で大きく。説明は文節で2行に割る。締め行は置かない。

大量のログ → 探す → 抜き出して並べる → 仕分けて渡す → 人

- 探す：エラー時刻と／該当行を見つける
- 抜き出して並べる：必要な情報だけを／取り出す
- 仕分けて渡す：重さで要約し、／要る順に渡す
- 人：見るべきものから／確認する

## 6. 苦手が出る場面では、人がそばにいるよ

様式：場面は文字＋オレンジの線、渡す先はベタ面の帯。「分からないものは…」は締め行にせず、薄い吹き出しで友達の約束として置く。

- 複数の資料をまたぐ判断 → 人や強いモデルへ渡す
- 原因の連鎖を追う仕事 → 人が最後まで見る
- 決まった形の解析 → コードに任せる

帯：分からないものは、無理に答えず、分からないまま上げるよ

## 7. まとめ

様式：静かに閉じる。吹き出しのチップ1つと、中央の3行だけ。

怖がらなくていいよ。得意と不得意を知れば、ネモトロンは、ちゃんと役に立つ友達になるよ。
