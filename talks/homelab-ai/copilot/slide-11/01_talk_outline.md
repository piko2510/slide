## 発表の目的

**自宅AI環境の裏側 — 自分がAIの段取り係にならないために。**

社内エンジニア向け、10分発表＋質疑5分、本編13枚です。
ハーネス、Jev、各モデルの配役を知っていることは前提にしません。
モデルの新しさや台数ではなく、人が毎回説明・中継・再開指示をしなくても、事情と意図を踏まえた仕事を任せたい、という設計目的を伝えます。
完成宣言ではありません。目的、設計上の仕組み、検証すべき効果を区別します。

構成の基準は2026年9月24日の公開構成案です。
これは現在の実機を再調査した報告書ではありません。生成時にモデル配役や未確認の成果を勝手に更新しないでください。

## 本編を通す説明用の依頼

> このIssueの不具合を修正して。前に決めた方針は守って、PR作成まで。mergeはしない。

架空の説明例です。実際の成功事例や全経路の完走記録ではありません。
要求確認、過去の方針の取得、情報の選別、実装の委任、検証、終了点を同じ例で説明します。
すべての相談をIssue化する意味ではなく、PRやCIが不要な依頼もあります。
この例ではPR作成までで終了し、mergeを実行する話に変えません。

## 用語と責務

| 用語 | 本発表での意味 | 誤解させない点 |
| --- | --- | --- |
| Proxmox | 自宅の作業環境を載せる土台 | 全モデルのローカル推論を意味しない |
| Codex | モデルへの入力、ツール実行、結果の返却を支える実行環境 | 自作の固定順序エンジンとは説明しない |
| 親Astra | 目的、直接委任、結果評価、最終受入を持つ判断役 | 実装担当と同じ責任にまとめない |

| Luna | 対象・終了点が明確で、根拠と照合できる仕事の担当 | Sol配下の段階や文章整形専用とはしない |
| Grokなどの外部担当 | 実装等の専門作業を、外部CLI経由で行う担当 | Codexのnative agentと同じ起動方法ではない |
| 子Astra | 親が具体的な能力不足を判断したときの振り直し先 | 失敗回数による自動昇格ではない |
| Git | 差分、branch、commit、worktreeを確認する場所 | GitHubと同じものとはしない |
| GitHub | Issue、PR、レビュー、CI等の要求と開発状態 | 会話の完了報告だけで状態を決めない |
| コンテキスト基盤 | 事情、理由、制約、時点、出典を取り出す仕組み | 保存成功と正しい利用は別 |
| Jev | 参考情報の意味に関する限定的な判定を前処理へ使う部品 | 司令塔、権限決定者、全入力の削除装置ではない |
| AGENTS.md | AIが読む共通規則 | 読んだだけで実行権限が変わるわけではない |
| Skills | 仕事に応じて参照する手順 | 追加の担当者や追加権限ではない |
| 設定・Hooks | 担当・権限の設定と、イベント時の処理 | 指示文と機械的処理を同一視しない |

## 図で守る関係

1. 自宅側に作業環境とコンテキスト基盤、外部側にクラウドの推論・Jev・GitHubを置きます。
2. 基本ループには結果から判断への戻り線があります。結果が出るたび終了する直列図にはしません。
3. Jevへ渡す選別対象は参考資料です。必須指示・権限・受入条件は別経路で保持します。
4. 配役は親から直接割り当てます。Sol→Luna→子Astraという固定の昇格階段を描きません。
5. 通常worker、外部CLI、独立read-onlyプロセスは、役割と起動方法を分けて説明します。
6. 担当の返答、検証結果、親の受入は区別します。確認なしの合格・mergeを描きません。

## 本編へ持ち込まない内容

定時自動実行、LINE入口、旧ハーネスの長い開発史、内部ファイル全文、認証経路、モデルの細かな版・推論強度は対象外です。
ただし「標準ループを使い、自作は接続部分に絞る」という設計判断は第4枚で扱います。
費用削減、時間短縮、精度向上、無監督完走の数値や保証を追加しません。
主題は開発自動化だけではありませんが、この13枚の具体例は1つに固定します。
