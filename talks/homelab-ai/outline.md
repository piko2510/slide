# AIに任せるために、何を作らないか

## 自宅AI環境を作り直して分かった、Harness・モデル・文脈の責務分離

この発表は、現在のAI構成をきれいに並べるだけの紹介ではありません。

AIへ仕事を任せるために管理機構を作りすぎ、その管理機構まで自分の仕事になった結果、
**何を捨て、何を標準へ戻し、どの判断だけを残したか**を13枚で追います。

## 13枚の構成

| # | 題目 | 話すこと |
|---:|---|---|
| 1 | AIに任せるために、何を作らないか | 完成構成ではなく、作りすぎて削った設計判断の話。 |
| 2 | AIを使うほど、なぜか自分の仕事が増えた | 説明・選択・中継・再開。人間がオーケストレーターになっていた。 |
| 3 | ならば、Harnessに全部管理させればいい | Router、state、gate、retry等を積み上げた理由。 |
| 4 | 安全にするほど、Harness自身が仕事になった | 仕事本体よりHarnessを成立させる管理が増えた。 |
| 5 | 37万5900行消して、標準機能へ戻った | 独自Harness撤去。Codex / Git / GitHubへ責務を戻す。 |
| 6 | ただし、複雑さは消えない。場所が変わる | コードを削るとAGENTS.mdが肥大化。 |
| 7 | 一番賢いモデルに全部考えさせるのも違った | Astraへ寄せすぎる副作用。 |
| 8 | 仕事の難しさではなく、判断の種類で分ける | 現在のモデル分担。 |
| 9 | それでも残った「全部読ませる」問題 | Context DBの次に情報選択がボトルネックになる。 |
| 10 | JevはAIを増やすためではなく、AIの仕事を減らすため | 限定意味判断を生成モデルから剥がす。 |
| 11 | そしてJevにも、選ばせてはいけないものがあった | 実際の失敗から必須情報を選別対象外へ。 |
| 12 | 今の構成は「シンプル」ではなく「責任の置き場所が明確」 | 現在の環境を責務マップとしてまとめる。 |
| 13 | AIの段取り係にならないために、Harness自身も管理しない | 何を自分で持たないかを設計するという結論。 |

## 実測値の扱い

旧Atem Harness撤去commitのGitHub差分は **300 files / 375,900 deletions / 629 additions**。
これはGitHub差分上のdeletionsであり、純粋な手書きLOCや改善率ではありません。

後の整理Issue起点ではAGENTS.mdが一週間で **21,344 bytes → 39,242 bytes**。
これも実消費トークンではなくUTF-8のファイル量です。

## 最終メッセージ

> AIに仕事を任せるために、管理システムを作りすぎた。  
> だから今は「何を自分で持たないか」を設計している。

複雑さをゼロにするのではなく、**散らからないように責任の置き場所を決める**ことが現在の設計です。
