# わしの家のAI環境｜発表構成 v4

副題：自宅サーバーとCodexで、AIに仕事を任せる

社内エンジニア向け。
本編10分、質疑5分。
開催日は未定。

## 発表の軸

家でこんなAI環境を組んでいる。
任せるために苦労した。
その結果、今はこの構成で、こう仕事を進めている。

最初に現在の家の全体像を見せる。
目的と人間に戻っていた負担を説明し、独自ハーネスの過去話は05の一枚で畳む。
06以降は現在のCodexの動作が主役。
標準化やPR作成を目的にせず、本人が事情説明・中継・再開係をしなくてよい環境に戻って締める。

## 13枚の構成

| # | 表示見出し | この一枚の役割 | 時間 |
|---:|---|---|---:|
| 01 | わしの家のAI環境 | 自宅の構成と使い方の紹介として入る | 20秒 |
| 02 | 自宅VMとクラウドを、こうつないでいる | 自宅の作業・情報基盤とクラウド推論、GitHubの配置を見せる | 45秒 |
| 03 | 任せたいのは、答えではなく一件の仕事 | 委任した到達点まで進めたいという目的を具体化する | 35秒 |
| 04 | 任せたはずなのに、俺が段取り係だった | 説明・中継・再開・実物確認が本人に戻る負担を示す | 40秒 |
| 05 | 独自ハーネスは捨てて、標準へ戻した | 自作制御基盤の話を一枚で終える | 30秒 |
| 06 | Codexが、モデルとツールを往復させる | 現在のハーネスをプログラムの動きで説明する | 60秒 |
| 07 | 親は判断、担当は実行、別担当が確認 | 親Astra、Sol、Luna、Grok、確認担当の配役を示す | 55秒 |
| 08 | ルール・手順・機械処理を分ける | AGENTS.md、Skill、Hook/CIと実行権限を区別する | 45秒 |
| 09 | 一件の依頼は、確認と差し戻しまで回す | 到達点・検証・受入・修正・許可された反映を一続きで示す | 65秒 |
| 10 | 毎回の事情説明を、コンテキスト基盤へ | 決定・理由・制約・訂正を必要時に取り出す目的を示す | 45秒 |

| 13 | AIの段取り係をしなくていい環境へ | 家でこの構成を作っている目的へ戻って締める | 30秒 |

## 時間配分

| 範囲 | 内容 | 時間 |
|---|---|---:|
| 01〜03 | 自宅環境と目的 | 100秒 |
| 04〜05 | 人間の負担と独自ハーネス撤去 | 70秒 |
| 06〜12 | 現在のCodexの動き・入力基盤・実利用の確認 | 365秒 |
| 13 | 目的に戻る結論 | 30秒 |
| 説明枠の合計 | 9分25秒 | **565秒** |
| 切替・間の余裕 | 35秒 | **35秒** |
| 本編 | 10分 | **600秒** |

時間は制作時の枠であり、台本を読み上げた実測値ではない。
本番前に通し読みし、長ければ台本外の技術注記を話さず、独自ハーネスの枝葉を増やさない。

## 本編に持ち込まないもの

独自ハーネスの詳細な開発史、削除行数を主役にした演出、一般的なAI入門、モデル性能ランキング、LINE秘書等の別用途、毎時timerの詳説は扱わない。
実行例を成功実績に見せず、Jevの接続設計と実運用の受入を区別する。
新しい監督agentや独自実行基盤を提案する発表にしない。
